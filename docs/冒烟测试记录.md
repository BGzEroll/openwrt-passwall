### 硬件证据摘要

取证在连接仍有流量时完成；连接关闭、进入 TIME_WAIT 后，卸载标记和 PPE 表项被回收属于正常行为。

| 流量 | conntrack | PPE 证据 |
| --- | --- | --- |
| IPv4 TCP 代理，源端口 41010 | `[HW_OFFLOAD] mark=1` | BND 表项，包数 195 → 334，字节 266615 → 454581。 |
| IPv4 TCP 直连，源端口 41012 | `[HW_OFFLOAD] mark=0` | BND 表项，实际计数 182 包、243770 字节。 |
| IPv6 TCP 代理，源端口 41014 | `[HW_OFFLOAD] mark=1` | 正、反向 BND 表项；返回方向包数 666 → 1430，字节 965117 → 2084393；发送方向的下一跳 MAC 对应现有代理网关、VLAN 2。 |
| IPv6 TCP 直连，源端口 41015 | `[HW_OFFLOAD] mark=0` | BND 表项，包数 107 → 171，字节 152542 → 238276。 |
| IPv4/IPv6 UDP 代理 | 两个地址族均为 `[HW_OFFLOAD] mark=1` | 已验证硬件卸载标记和完整请求响应；未采集到对应 UDP 的 PPE 分项计数，不将其写成已取得 PPE 计数证据。 |

PBR 下原生 fw4 的软、硬件加速开关保持关闭；实际卸载来自 Passwall 自建 flowtable，二者不矛盾。上述 TCP 证据确认了真实硬件转发，而不只是存在 `flags offload` 配置。

补测过程中未发现新的插件代码缺陷。主路由的 Passwall、DHCP、防火墙配置恢复到补测前，代理核心 PID 保持一致，WAN 在线；临时 ACL、trace 表和监控进程均已移除。

## 发现并修复的问题

### 本机 DNS 与劫持冲突

同时开启本机代理和 DNS 劫持时，发往外部 DNS 的本机流量被标记并经 `lo` 回到 PREROUTING。原来的客户端 DNS 提前返回规则也匹配这些包，阻止它们进入 TPROXY，随后还可能被 DNS NAT 重定向，导致查询超时。

客户端 DNS 提前返回和 DNS 劫持入口现在都排除 `lo`。客户端查询继续交给 DNS 劫持，本机已经标记的查询进入 TPROXY。修复后，劫持开、关两种状态下的 IPv4/IPv6 DNS 实际查询均通过；架构回归检查也已更新。

### 短延迟开机时 PBR 路由失败

真实重启时，启动延迟只有 1 秒，网口已 UP，但 DHCP 地址尚未取得。原逻辑立即添加网关路由并失败，未留下运行标记，后续网络事件因而无法恢复服务。

现在分别检查每个地址族是否已有可用地址，排除 IPv6 DAD 中或 DAD 失败的地址。尚未就绪时保留不可达保护，网络就绪后热更新路由；接口已有地址时的错误网关仍然报错并回滚。hotplug 不再在排队前过滤运行标记，避免丢失启动期间的通知，是否运行仍由持锁后的 reload 判断。

另补齐原生 init 的 `running` 查询，避免系统查询服务状态时打印命令帮助。

在测试机运行 `tests/test_file_rule_reload.sh`（需显式设置 `PASSWALL_TEST_ROUTER=1`，会临时修改配置并重启服务，禁止在主路由运行）：

- 只修改代理域名文件后执行配置重载，仅 ChinaDNS-NG PID 改变，Xray PID 保持不变；重复重载 PID 均不变。
- 直连域名文件从空到非空、再删除，均触发 ChinaDNS-NG 更新，缺失文件按空列表处理。
- 通过真实 `update_rules` 入口发布 GFW 文件，仅 ChinaDNS-NG 更新。

- 停止服务后的规则重载不重新启动服务。

## 全新刷写后的节点创建漏验

用户全新编译并刷写后，通过 UI 创建的节点缺少 `type=Xray`，核心日志反复报“不是 Xray 节点”。主路由相关 Lua 文件与 `/rom` 原文件一致，故障不是用户修改程序文件造成的。

根因：节点类型被改为只读 `Value`，但仍依赖该字段的 `write()` 设置固定类型；原生 CBI 的 `Value.parse()` 遇到 `readonly` 直接返回。同时创建节点时只建立了 `nodes` 段，没有写入 `type`。

此前默认空配置页面、已有节点页面的读取与核心测试没有覆盖“空节点列表→点击添加→填写→保存→应用→重新打开”的完整写入流程，因此之前的收尾结论范围过大。该流程属于基本验收，不能用实际固件安装未测的边界替代。

修复：节点创建时写入固定核心；核心显示使用 DummyValue，并在保存前保证 `type=Xray`，同时修复之前创建的缺字段节点。测试机使用默认空配置和真实 Chromium 操作新增 SOCKS 节点，验证保存、应用、重新打开、字段落盘，以及旧节点缺失类型时再次保存可补齐；UI 创建的节点通过 Xray 实际配置生成与 `run -test` 校验。回归脚本为 `tests/test_node_creation_ui.py`，需专用空配置测试机和 Playwright。主路由仅只读取证，未部署本次修改。
